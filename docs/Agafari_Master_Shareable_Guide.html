Section 02

Domain-Driven Design (DDD) Architecture & Security

A hardened Next.js App Router monolith backed by MySQL, structured cleanly into 4 distinct architectural layers.

🏗️ 4-Layer DDD Architecture
  • Domain Layer (src/domain/): Rich domain entities, value objects, domain events, and repository interfaces. Completely decoupled from frameworks.
  • Application Layer (src/application/): Orchestrates use cases, application services, input/output DTOs, and transaction boundaries.
  • Infrastructure Layer (src/infrastructure/): MySQL connection pool, repository implementations, Upstash Redis rate limiting, and Sentry error tracking.
  • Presentation Layer (src/app/ & components/): Next.js Server & Client Components, API route handlers, and modular feature components.
🛡️ Security & Hardening Features
  • JWT Cookie Auth: Cryptographic HMAC SHA-256 tokens stored in secure, HttpOnly, SameSite cookies.
  • Salted Password Hashing: PBKDF2-SHA512 algorithm with 16-byte random cryptographic salts.
  • Rate Limiting: Dual-layer protection (Upstash Redis + in-memory token bucket fallback) against brute force attacks.
  • Telemetry & Masking: Sentry integration with automatic masking of sensitive PII (passwords, emails, phone numbers).
  • Strict Env Validation: Zod schema validation ensuring all secrets exist before app startup.
